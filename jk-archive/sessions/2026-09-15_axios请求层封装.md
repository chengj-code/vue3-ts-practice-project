# Axios 请求层封装 — 分层封装 axios，统一 token 注入/错误提示/泛型返回

## 需求

练习项目阶段 1 任务（spec Task 3）：封装 `src/api/request.ts`，包含 axios 实例、请求拦截器（注入 Token）、响应拦截器（业务 code 解析 + 统一错误提示）、泛型响应类型，并按 modules 组织接口模块，与 mock 层 `{ code: 0, message, data }` 约定对齐。

## 方案

四层结构，职责分离：

1. **类型层** `src/api/types.ts`：`ApiResponse<T>`（与 mock/_utils.ts 的 MockResult 对齐）、`PageQuery`、`PageResult<T>`、`UserInfo`
2. **实例+拦截器** `src/api/request.ts`：
   - `axios.create({ baseURL: import.meta.env.VITE_API_BASE_URL })`
   - 请求拦截器：`useUserStore()` 在函数体内调用（避开 Pinia 未安装 + 循环依赖），token 塞 `Authorization: Bearer`
   - 响应拦截器：`code === 0` 时剥壳 `return res.data`，否则 ElMessage 提示 + `Promise.reject`；HTTP 错误走 `handleHttpError`（401 清 token 跳登录，带 `isRedirecting` 防并发重复跳转）
   - 出口 `request` 对象只暴露 get/post/put/delete，泛型写法 `service.get<T, T>`（关键：第二个泛型钉死 R，对齐剥壳后运行时行为）
3. **接口模块** `src/api/modules/user.ts`、`list.ts`：调用处填业务类型，如 `request.post<LoginResult>('/login', data)`
4. **配套**：`src/stores/user.ts`（token/userInfo + persist 持久化）、`main.ts` 注册 persistedstate 插件

核心类型技巧（拦截器剥壳导致类型断点，用 `<T, T>` 接回）：

```ts
// axios 签名: get<T, R = AxiosResponse<T>, D = any>(...): Promise<R>
// 只写 get<T> 时 R 默认 = AxiosResponse<T>，与剥壳后运行时返回裸 T 不一致
const request = {
    get: <T>(url: string, params?: object) => service.get<T, T>(url, { params }),
    post: <T>(url: string, data?: object) => service.post<T, T>(url, data),
    put: <T>(url: string, data?: object) => service.put<T, T>(url, data),
    delete: <T>(url: string, params?: object) => service.delete<T, T>(url, { params }),
}
```

## 遇到的问题与解决

| 问题 | 原因 | 解决 | 教训/可复用点 |
|------|------|------|--------------|
| `persist` 不在 DefineSetupStoreOptions 中（ts2345） | persistedstate 的类型靠 `declare module 'pinia'` 注入，未 import 插件模块则类型扩展不加载 | main.ts `import piniaPluginPersistedstate` 并 `pinia.use(...)` | 见模式卡片：pinia-plugin-persistedstate 类型扩展 |
| 拦截器 `return res.data` 报 ts2345（unknown 不能赋给 AxiosResponse） | axios 拦截器签名硬编码要求返回 AxiosResponse，类型系统无法表达"剥壳改变返回形态" | `return res.data as AxiosResponse` 边界处受控断言 | 谎言只留在拦截器边界，出口 `<T, T>` 把类型掰回真实 T |
| 只写 `get<T>` 时业务层类型错位 | R 默认 = AxiosResponse<T>，类型认为数据包在 .data 里，运行时已剥壳 | `service.get<T, T>` 显式钉死 R = T | 最阴险：按类型写 `res.data.token` 编译通过但运行时 undefined |
| ElMessage 弹出无样式（裸图标+文字） | unplugin-vue-components 只处理模板标签；ElMessage 是函数调用，样式链路未触发 | main.ts 手动引入 message/message-box/notification/loading 四个样式 | 见模式卡片：Element Plus 函数式组件样式缺失 |
| 500 错误提示成"请求超时" | `??` 优先级高于 `?:`，`(a ?? b) ? c : d` 中命中 ERROR_CODES 恒为 truthy | 三元加括号：`ERROR_CODES[status ?? 0] ?? (error.code === 'ECONNABORTED' ? ... : ...)` | ?? 与 ?: 混用必须加括号 |
| baseURL 为 undefined / 错误提示为空 | env 变量名抄错 VITE_BASE_URL；mock 字段 message 抄成 msg | 对照 .env.development 与 mock/_utils.ts 修正 | 跨文件约定（env/mock 字段名）抄写时要对照源头 |
| 业务失败时调用方 catch 不到 | 业务 code 非 0 时误写 `return response` | 改为 `Promise.reject(new Error(message))` | 拦截器 reject 后必须继续抛，否则错误被吞进 then |
