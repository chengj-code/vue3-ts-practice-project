# 登录鉴权 — LoginView + 路由守卫 + redirect 链路

## 需求

spec Task 6：创建登录页、路由守卫，实现未登录拦截 → 登录 → 回到来源页的完整链路。与 Task 3（user store + loginApi）、Task 5（布局登出按钮）、request.ts 401 跳转衔接。

## 方案

1. **LoginView**：el-form + `ref<FormInstance>` + `validate()` reject 捕获 + loginApi → setToken/setUserInfo → ElMessage.success → redirect 跳转；redirect 值从 `route.query.redirect ?? '/'` 取
2. **路由守卫**：顶层 `/login` 路由标 `meta.requiresAuth: false`；`beforeEach` 用 vue-router 4 函数式写法（return true / return location）；已登录访问登录页踢回首页；无 token 时 `to.fullPath` 作为 redirect 参数塞到登录页 query
3. **request.ts 401** 与 **DefaultLayout 登出** 统一走 `router.push('/login')` → 守卫放行 → redirect 链路闭环

## 遇到的问题与解决

| 问题 | 原因 | 解决 | 教训/可复用点 |
|------|------|------|--------------|
| `router.replace(redirect)` 类型报错 | `route.query.redirect` 类型是 `LocationQueryValue`（含数组可能性），TS 不认可直接传给 replace | `as string` 断言 + `??` 兜底 | vue-router 4 query 类型宽松，业务层收窄 |
| 守卫里 `name: '/login'` 匹配不到 | vue-router name 是字符串标识（路由定义里是 'login'），path 才是 '/login' | 改用 `path: '/login'` 或 `name: 'login'` | name ≠ path，匹配前看清路由定义 |
| 守卫里 useUserStore 调用位置 | 误放模块顶层会触发 Pinia 未安装 + 循环依赖 | 放守卫回调函数体内 | 与 request.ts 拦截器同源原则 |
| validate 失败产生 unhandled rejection | validate() 校验不通过时 reject，没 catch 会冒泡 | 外层 try-catch 吞掉 | Element Plus 表单校验自带 reject 语义，必 catch |
| 登录失败双弹提示 | LoginView catch 里也弹了 ElMessage，但 request.ts 拦截器已弹过 | LoginView catch 静默（留注释说明），拦截器统一管错误提示 | 错误提示集中在拦截器，业务 catch 只防 unhandled rejection |
| App.vue 残留脚手架样式 | Task 3 临时注释掉 handleLogin 后 import 和 header/nav 样式还在 | 随本任务清理干净 | 临时代码用完即清，别让"注释"变成"遗留" |
