# 权限控制（Task 11）— 类型层、判断层、路由层已完成；按钮指令/菜单过滤待做

## 需求

spec Task 11：路由级权限（meta.roles + 守卫）、按钮级权限（v-permission 指令）、无权限页。采用 RBAC 双层模型：mock 登录返回已含 `roles`（角色，粗粒度管路由）与 `permissions`（权限码，细粒度管按钮）。

账号：admin（roles=['admin']，四个 user:* 权限码全有）/ user（roles=['user']，仅 user:list）。

## 方案（六步拆分，逐步确认）

1. **类型层**：env.d.ts 模块增强 vue-router 的 RouteMeta（title/icon/requiresAuth/roles）
2. **判断层**：usePermission 收口 hasRole/hasPermission（角色 + 权限码），守卫/菜单/指令复用同一实现
3. **路由层**：/user/list 配 roles:['admin']；守卫三层门禁（白名单 → token → 角色）；新增 /403 页
4. 按钮层：v-permission 指令（待做）
5. 菜单层：DefaultLayout 按 hasRole 过滤菜单（待做）
6. 全量走查验收（待做）

## 遇到的问题与解决

| 问题 | 原因 | 解决 | 教训/可复用点 |
|------|------|------|--------------|
| 加 `declare module 'vue-router'` 后 createRouter/RouterView 全部 TS2305 消失 | env.d.ts 无顶层 import/export 是脚本文件，declare module 被当成"模块替身"而非"模块增强"，整体遮蔽官方类型 | 加 `export {}` 使其成模块文件，declare module 自动变为增强 | 增强已存在的包必须在模块文件里；declare module 在脚本文件=环境模块声明=顶包。详见 patterns/declare-module类型顶包与声明合并.md |
| 加 export{} 后 VITE_USE_MOCK 静默退化为 any | 文件变模块后顶层 interface ImportMetaEnv 变局部接口，不再与 vite 全局接口合并；vite 自带 `Record<string, any>` 索引签名兜底所以不报错 | declare global { ... } 包裹两个全局接口 | 类型增强失效常是静默的：不报错 ≠ 生效，悬停看实际类型 |
| requiresAuth 写成 requiredAuth | 字段拼写少 s；vue-router 5 RouteMeta 继承 Record<PropertyKey, unknown>，拼错不报错只变 unknown | 与全项目（路由表/守卫）统一为 requiresAuth | 增强类型后拼错本应报错，索引签名场景仍要靠人工对齐 |
| usePermission 第一版 `role?.includes(item) \|\| item` 永远 truthy | item 是非空字符串恒为真值，required 形同虚设，普通用户被判 admin 权限 | 改为交集 `required.some(item => mine.includes(item))` + 显式 isAdmin 短路 | 权限判断最致命的是"恒真"表达式；真值检查用布尔表达式别用业务对象本身 |
| hasAny 写成 `required.length` 漏 === 0 | 数字直接进布尔：length=1 truthy 导致"配了角色要求反而直接放行" | `required.length === 0` | length 是数字不是布尔，显式比较 |
| 返回类型出现 boolean \| undefined | 可选链在 userInfo=null 时短路成 undefined | userInfo?.roles ?? [] + isAdmin ?? false，出口严格 boolean | 守卫 !undefined 碰巧能工作是"蒙对"，出口类型必须收窄 |
| 403 守卫重定向死循环风险 | /403 若需鉴权，无权限用户跳 /403 会再被守卫拦 | /403 配 requiresAuth:false 走白名单 | 错误页/登录页必须在白名单内 |

## 关键设计约定

- **空入参 = 不设限**：hasRole() / hasRole([]) 恒 true，路由不配 roles 即所有登录用户可进（dashboard 即此场景）
- **admin 短路只查 roles**：'admin' 是角色不是权限码，permissions 数组里永远不会出现它
- **判断顺序**：不设限 → 超管 → 交集，顺序不可乱
- **store 调用时机**：usePermission 在守卫回调体内、指令钩子内部调用，禁止模块顶层（pinia 未就绪）
- **403 而非登录页**：有 token 但角色不足是"合法用户越权"，跳登录语义错误
