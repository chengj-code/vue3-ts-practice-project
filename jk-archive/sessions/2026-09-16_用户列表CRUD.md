# 用户列表 CRUD — Task 9

## 需求

spec Task 9：实现完整 CRUD 页面，消费 Task 8 的三个 composables。验收 TR-9.1 ~ 9.4（列表加载、查询分页、新增、编辑、删除）。

## 方案

### mock 改造

原 mock 只支持分页，加 name/status 筛选。注意 query 参数全是字符串，`'false'` 严格判断才能正确过滤。

### useTable 消费

- 泛型双参数：`<UserItem, { name?: string; status?: string }>` 显式传 Q 对齐 mock
- 模板直接 `v-model="query.name"`，删掉 searchForm 避免双状态不同步
- handleSearch 只设 `page.value = 1`，靠 watch 自动 fetch（**不手动调 fetch**，避免双请求）
- handleReset 直接调 useTable.reset()，它内部清 query + 回第一页 + 自动 fetch

### useModal 消费

- dialogVisible / dialogFormData / open / close / confirm 解构自 useModal
- dialogForm（reactive）和 dialogFormData（useModal 返回）**两套状态**：watch dialogVisible 打开时 Object.assign 同步
- onConfirm 里区分新增/编辑：`dialogFormData.value?.id` 存在 → updateUserApi，否则 addUserApi
- onConfirm 成功后 ElMessage + fetch()（useTable.fetch 闭包内直接引用）

### 技术踩坑汇总

| 坑 | 教训 |
|---|---|
| `<el-table<UserItem>>` 模板不能写泛型 | Vue SFC 模板是 HTML 超集，TS 泛型只在 `<script setup>` 里有效 |
| handleSearch 双请求 | page 变化会 watch 触发 fetch，手动再加一次就是双请求 |
| `<Q>` 默认值太宽松 | 显式传 `<Q>` 让 TS 帮你守住 mock 期望的类型 |
| onConfirm 必须补 fetch | useModal 只管开关弹窗，业务层自己负责刷新列表 |
| dialogForm 缺 createTime | addUserApi 期望完整 UserItem 字段，新增时 mock 会替换 createTime |
| handleDelete 边界 | 删到当前页空了要回退 page，靠 watch 自动 fetch |
| ElMessage 要显式 import | useModal 的 onConfirm 回调里用 ElMessage 不能靠 auto-import |
