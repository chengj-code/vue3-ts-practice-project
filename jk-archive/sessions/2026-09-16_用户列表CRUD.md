### Task 10 关键决策：useForm 职责边界

Task 9 时 UserListView 只用了 useTable + useModal，表单数据是手动 `reactive dialogForm`。Task 10 接入 useForm 后，发现 **同时存在 3 个运行时 bug**，根因都是职责混淆：

| Bug | 根因 | 修法 |
|-----|------|------|
| API 被调两次 | useForm.onSubmit 和 useModal.onConfirm 都调 API | API 逻辑全放 useModal.onConfirm，useForm.onSubmit 空实现 |
| 校验的不是用户输入 | el-form 绑的是 dialogForm（reactive），useForm 的 form 是 initialData 快照 | 删掉 dialogForm，el-form `:model="form"` 直接绑 useForm 返回的 form |
| formRef 有两份 | 模板手动声明 `ref="formRef"` 和 useForm 返回的 formRef 并存 | 删掉手动 formRef，用 useForm 返回的 formRef |

**最终职责划分**：

```
useForm  → 管表单数据 + validate + loading
useModal → 管弹窗开关 + API 调用 + 成功后 close
handleSubmit → 串联两者：submitForm() → confirm()
```

### 异步校验器（用户名查重）

- Element Plus async validator 用 `callback` 模式（不要混用 `return true`）
- 空值 → 交给 required 规则拦截，validator 直接 `callback()`
- 编辑模式跳过查重 → `callback()`
- 接口异常兜底 → `callback()` 不阻塞提交
- mock 路由：`GET /api/user/check?name=xxx`（注意之前误写 POST /api/user 和新增路由冲突）

### 技术踩坑汇总（本次新增）

| 坑 | 教训 |
|---|---|
| mock 路由冲突：两个 POST /api/user | vite-plugin-mock 只匹配第一个，查重接口必须换路径和 HTTP 方法 |
| Element Plus async validator callback/return 混用 | 统一用 callback：校验失败 callback(new Error)，其他情况 callback() |
| useForm 泛型约束过严 `Record<string, unknown>` | interface 没有索引签名，改成 `F extends object` 更宽松 |
| useForm 接入时忘记清旧状态 | dialogForm/submitLoading/formRef 手动声明和 useForm 返回的重复，必须删掉旧的 |

### LoginView 用 useForm 重写（消费方 2，TR-8.2 验证）

Task 6 时 LoginView 是手写 validate，这次改成 useForm 消费，验证 composable 的通用性：

- el-form `:model="form"` + `ref="formRef"` + `:loading="loading"` 全部对齐 useForm 返回值
- rules 用 `FormRules` 类型标注 → validator 参数自动推断（不用 `any`）
- password 规则拆两条：`required: true` 管必填、validator 只管长度 ≥ 6（单一职责）
- onSubmit 里调 loginApi → setToken/setUserInfo → router.replace(redirect)
- catch 空实现：响应拦截器已统一 ElMessage 提示，业务层不重复弹

**踩坑**：Element Plus async validator 用 `FormRules` 类型标注后，三个参数自动推断为 `FormItemRule` / `unknown` / `(error?: string | Error) => void`，不需要手动写 any。
