# useTable 查询失效与重复请求修复 — watch 触发语义排查链

## 需求

用户列表页点「查询」按钮无任何反应；修复后又暴露「翻页后再筛选会掉两次接口」的重复请求问题。最终收敛为一个既能触发、又不重复请求的 useTable 设计。

## 方案（问题演进 4 阶段）

### 阶段 1：查询无反应 —— 根因是 page 同值赋值不触发 watch

- 消费方写法：`handleSearch = () => { page.value = 1 }`，指望 watch 自动 fetch
- useTable 只 `watch([page, pageSize])`
- **根因**：page 已是 1 时，`page.value = 1` 是同值赋值（`Object.is` 相等），ref setter 不触发依赖更新 → watch 不执行 → `fetch()` 从未被调用
- 症状特征：第 2 页点查询有效（2→1 有变化），第 1 页点查询无效——典型的「page 1 搜索 bug」

### 阶段 2：方案 C（watch query）失败 —— 对象引用比较

- 尝试把 query 加进 watch：`watch([page, pageSize, () => query.value], fetch)`
- **失败原因**：getter 每次返回**同一个对象引用**，v-model 改的是 `query.value.name`（内部属性 mutate），引用没变 → watch 不触发
- 若改 `deep: true` 能触发，但搜索框每敲一个字符就发一次请求，体验不可接受 → 放弃

### 阶段 3：显式 fetch + 状态标记 —— 标记残留 bug

- 第一版修复：`handleSearch` 里 `page.value = 1; fetch()` → 查询生效
- 新问题：第 2 页点查询时，page 2→1 触发 watch fetch + 手动 fetch = **两次请求**
- 尝试 `skipNextWatch` 状态标记屏蔽 watch → 推演出**残留 bug**：
  - 第 1 页点查询：标记设为 true，但 page 同值赋值 watch 不触发 → 标记无人消费
  - 下一次用户翻页：watch 触发却被残留标记吞掉 → **翻页失效一次**
- 教训：状态标记防重的致命弱点是「设了没人消费」的时序缝隙

### 阶段 4（最终）：条件 fetch —— 无状态标记，分支显式化

```ts
// watch 恢复纯净，只管真正的用户翻页
watch([page, pageSize], () => {
    fetch();
})

// 搜索：已在第一页就手动发（同值赋值不触发 watch），否则改 page 交给 watch
const search = () => {
    if (page.value === 1) {
        fetch();
    } else {
        page.value = 1;
    }
};

// 重置：分页参数均未变化时手动 fetch，否则交给 watch 触发
const reset = () => {
    query.value = {} as Q;
    if (page.value === 1 && pageSize.value === defaultPageSize) {
        fetch();
    } else {
        page.value = 1;
        pageSize.value = defaultPageSize;
    }
};
```

- 每个分支都明确知道请求由谁发出，不存在「标记设了没消费」的缝隙
- 依赖的两个 Vue 稳定语义：① ref 同值赋值（Object.is）不触发 watch；② 同一 tick 内 page + pageSize 同时变化，数组源 watch 只触发一次
- 消费方 `handleSearch = () => search()`，签名不变

## 遇到的问题与解决

| 问题 | 原因 | 解决 | 教训/可复用点 |
|------|------|------|--------------|
| 查询按钮无反应 | page 同值赋值不触发 watch，fetch 从未执行 | 显式调用（search 方法） | 「靠改分页值间接触发 fetch」是脆弱设计 |
| watch query 无效 | getter 返回同一对象引用，内部属性 mutate 不触发 | 不 watch query，查询走显式方法 | watch 对对象默认引用比较；deep watch 会让查询框每击键发请求 |
| 翻页后筛选掉两次接口 | watch fetch + 手动 fetch 叠加 | 条件 fetch：值没变就手动发，变了交给 watch | 防重优先用条件分支，慎用「跳过一次」类状态标记 |
| skip 标记残留吞翻页 | 第 1 页查询时 watch 不触发，标记无人消费 | 弃用标记，改条件 fetch | 状态标记必须有确定的生命周期，否则时序缝隙必出 bug |
