# T16 WebSocket 实时通信 — useWebSocket 状态机 composable

## 需求

任务书 T16：`useWebSocket` composable（连接管理、心跳、断线重连、消息回调）+ 消息中心页（状态徽标、实时列表、Notification 提醒）。无真实 WS 服务器可用，HTTP mock（vite 插件）帮不上 WS 长连接。

## 方案

**三层结构**：

1. `MockWebSocket`（src/mock/websocket.ts）：鸭子类型复刻原生 WebSocket 公开形状（readyState 常量 / onopen/onmessage/onclose/onerror / send/close），模拟服务端行为——300ms 握手、5s 轮播推送、ping→pong 应答（带 timestamp 供 RTT 计算）、`kill()` 模拟宕机（code 1006）。`window.__mockWsDown()` 全局拉闸入口（declare global 扩展 Window）供控制台/页面验证重连
2. `useWebSocket`（src/composables/useWebSocket.ts）：状态机 composable——三个定时器（心跳 interval / pong 超时 timeout / 重连 timeout）+ 一个 `manualClosed` 标志。状态流转 connecting → open → onclose →（manualClosed ? closed : reconnecting → connect 循环，上限 10 次）
3. `MessageView`：status 驱动四态徽标（EP 语义色，open 慢呼吸/reconnecting 快脉动）、messages.unshift 时间线、onMessage 回调弹 ElNotification

**核心设计决策**：

- **重连单一出口**：pong 超时判定假死后不就地重连，而是 `socket.close()` 绕道 onclose → scheduleReconnect——「发现死亡」与「处理死亡」分离，重连逻辑全项目只有一份
- **manualClosed 标志**：close() 先置标志再断开（原生 WebSocket 的 onclose 是异步事件，标志必须先行），onclose 据此区分主动关闭（终态）与异常断开（自动重连）——缺它则登出后后台无限重连
- **心跳 = 发出 + 确认回来**：每次发 ping 起一个 pong 超时倒计时，只发不等是「向空气喊话」（TCP 连接在但进程假死时 send 不报错）
- **onopen 里 reconnectCount=0**：计数衡量「连续失败次数」而非历史总数，否则服务端恢复后一次抖动就烧光重连额度
- **重连超限 → closed 终态**：机器放弃的地方交还给人（页面出现重新连接按钮，open() 手动恢复并重置标志/计数）
- **页面级连接**：composable 内部注册 onBeforeUnmount(close)，调用方零清理成本；将来全局化只需连接挂 App 级 + messages 换 Pinia store，composable 代码零改动

## 遇到的问题与解决

| 问题 | 原因 | 解决 | 教训/可复用点 |
|------|------|------|--------------|
| `window` 找不到（mock/websocket.ts） | 根目录 mock/ 被 tsconfig.node.json 包含（Node 环境、无 DOM lib） | 移到 src/mock/websocket.ts | HTTP mock（跑 Node）与 WS 模拟（跑浏览器）不是一类东西；「mock」名字会骗人，按运行时环境归 tsconfig 侧 |
| （设计防御）非 OPEN 时回 pong | send 的 200ms 延迟窗口内连接可能被 kill | 回 pong 前再查一次 readyState | 模拟真实网络时序竞态，延迟回调里状态要重查 |
| （设计防御）openTimer 残留 | 握手未完成时 close/kill，300ms 后回调会把 CLOSED 连接复活成 OPEN | teardown() 统一清两个定时器 | 模拟服务端也要防泄漏；清理函数覆盖所有已挂定时器 |
